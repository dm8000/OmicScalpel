# OmicScalpel

A Shiny app for exploring omics datasets (RNAseq, microarray, lipidomics) held
in a shared hub, and for adding new datasets and sample metadata through the
interface. Deployed on an HPC under shiny-server.

It used to be nine separate apps, one folder per URL. They are being merged into
one app with nine tabs. `legacy/` holds the originals until parity is confirmed;
they are the reference the converted modules get compared against, so **do not
edit them**.

## Layout

    app.R              single entry point: dashboardPage, nine tabs
    global.R           sourced by shiny first: config -> libPaths -> packages -> R/
    config/config.txt  every filesystem path, machine-local, not versioned
    R/config.R         base R only: it runs before the library path is set
    R/data_io.R        the only place that reads or writes the hub
    R/registry.R       what modules exist -- source of truth for app.R and tools/
    R/modules/         one file per tab: mod_<id>.R
    tools/             linter, tests, fixture builder, deploy
    data-sample/       synthetic fixtures, safe to version, 2 datasets
    legacy/            the nine original apps, frozen

## Invariants

- **Paths come from `config/config.txt`.** No literal `/n/shiny/...` anywhere.
  `.Renviron` is generated by `tools/sync-renviron.R`, never edited.
- **`R/data_io.R` is the only reader and writer of the hub.** A module that
  calls `read_excel` or `write_xlsx` directly has a bug.
- **Every id in a module is namespaced.** `ns()` in the UI, `session$ns()` for
  anything the server builds. `update*()` keeps its bare id.
- **Six modules do not choose their dataset.** `scope = "one"` in the registry:
  they read `ds()`. A surviving `input$dataset` fails the linter.
- **Saving announces itself.** `save_metadata()` bumps `metadata_version()`, so
  every tab re-reads. Do not add an invalidation call inside a module.

## Module contract

    <name>UI     <- function(id)
    <name>Server <- function(id, ds, meta, go_to = NULL)

`ds` is the active dataset (a reactiveVal), `meta` the shared metadata
(a reactive), `go_to(tab, dataset)` switches tab and dataset. Register it in
`R/registry.R`; nothing else needs to know.

## Before committing a change to a module

    Rscript tools/lint_ns.R [--single-dataset] R/modules/mod_<id>.R
    Rscript tools/smoke_test.R <id>
    Rscript tools/run_module.R <id>          # to look at it

`--single-dataset` for `scope = "one"` modules. Fixtures must keep two datasets:
with one, a tab that ignores the shared dataset passes by accident.

## Known, accepted, not fixed

Two people saving the same spreadsheet at once is last-write-wins. The
timestamped backups in `backups/` are the mitigation. File locking is separate
work; see `docs/ARCHITECTURE.md`.

## Working style

- Read before editing; edit surgically.
- Do not read a whole app to change five lines -- grep first.
- Never commit `config/config.txt`, `.Renviron` or the real `.xlsx`.
- Do not run `git commit` or `git push` unless asked.
